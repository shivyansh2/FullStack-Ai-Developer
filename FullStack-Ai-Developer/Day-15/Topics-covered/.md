## 📅 Day 15 — Authentication, AI Security & Scalability

### 🔐 Main Topic — Authentication and Security

**Authentication vs authorization**
- **Authentication:** Who are you? Example: logging in with email and password.
- **Authorization:** What are you allowed to do? Example: only an admin can invite users or change organization settings.

### 🤖 AI Security
The platform will use AI to help review compliance evidence, so study these risks:
- **Prompt injection** — malicious instructions hidden in uploaded documents
- **Data leakage** — one organization's evidence or AI responses exposing another organization's data
- **Secret exposure** — API keys or private configuration appearing in prompts, logs, or responses
- **Unsafe AI actions** — letting an AI model change controls or approve evidence without appropriate authorization and validation

> **Rule to remember:** AI output is untrusted input. Your backend must enforce permissions and validate any proposed action independently of the model.


### 🏗️ System Design — Latency, Throughput and Availability

**Latency** — how long one request takes to complete.
*Example: An API takes 180 ms to return compliance controls.*

**Throughput** — how many requests a system processes per unit of time.
*Example: An API handles 800 requests per second.*

**Availability** — the proportion of time a system is operational and accessible.
*Example: 99.9% availability permits roughly 8.76 hours of downtime in a 365-day year.*

**Key techniques to learn:** database indexing, caching, connection pooling, load balancing, timeouts, retries with backoff, and monitoring.

### 🤖 AI Engineering — Latency Optimization and Batching
For an AI-powered compliance platform, model inference may take longer than an ordinary API request.

- **Streaming** — show generated text as it arrives rather than waiting for the entire response
- **Batching** — process multiple compatible requests together to improve throughput
- **Caching** — reuse results only when the inputs and access permissions make reuse safe
- **Smaller models** — use an appropriate model for simple tasks rather than always using the largest one
- **Timeouts and retries** — handle slow or failed model calls safely
- **Asynchronous jobs** — move lengthy document analysis into a background worker
